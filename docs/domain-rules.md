# 领域边界与裁定规则

管理曲艺评奖的作品档案、人员资格、分阶段晋级、匿名评分、现场终评事件、申诉公示与获奖确认。

## 一、作品与人员谱系（ArchiveService）

### 作品档案
- 作品保存：曲种、文本版本沿革、首演时间、原创声明、作者、权利人、报送单位。
- 文本以指纹（`text_hash`）标识；改名或修改一律**追加新版本**，历史版本不覆盖、不删除，始终可查。
- 原创声明、首演登记挂在具体版本上。
- 已被并入重复谱系（`merged_into`）的作品不再接受新版本，新版本登记在主作品下。

### 人员档案
- 保存：年龄证明（以证明文件记载出生日期为准）、所属单位关系（允许多段、并行，支持随不同院团参演）、演职关系（精确到作品版本：作者/演员/权利人/其他演职）、赛区经历、历史获奖。
- 演职关系随版本演进：换角时旧版本演员标记"退出"，新版本登记接替演员。

### 疑似重复作品——关键授权边界
1. 名称相似度扫描（含相同文本指纹）**只产生线索**（`DuplicateSuspect`），绝不自动合并。
2. 只有**授权人员**（`AUTHORIZED_OFFICER`）可以确认或否绝线索；秘书处无权。
3. 确认必须有**实质证据**之一：相同文本指纹、共有作者/权利人、或类型为"文本同一性鉴定/权利人同一性证明/作者身份证明"的附件。仅名称相似（无论附何种其他材料）一律拒绝。
4. 确认后建立重复关联组（`duplicate_group_id`），较早作品为主作品，被并入作品标记 `merged_into`；确认人、依据、证据、时间全部留痕。否绝则两作品保持独立。

## 二、轮次封存与资格复核（RoundService）

- 轮次：初评、分赛区（必须注明赛区）、现场终评。
- 秘书处登记材料并做**完整性检查**（按轮次要求必备材料类别）；完整性检查不接触评分身份。
- **初评结束封存一次、各分赛区结束分别封存**：对材料清单与晋级结论分别取 SHA-256 指纹快照（`RoundSeal`），封存后任何追加/改写抛 `SealedError`；`verify_seal` 可重新计算指纹比对。
- 晋级结论同时建立奖项候选（`Candidacy`），并在当时**冻结资格事实快照**（年龄、单位、演职、历史获奖、原创/首演/权利等）。
- **后补证明**：原轮次封存后提交的材料只能进入资格复核队列（`SupplementaryEvidence`），由复核人员/组委会给出采信结论；采信内容只叠加到候选资格供后续轮次使用，**绝不进入原轮次材料、不改变封存指纹与原晋级结论**。

## 三、评委回避与匿名评分（JuryService）

### 回避
- 组委会登记评委并可录入评委主动声明的利害关系人。
- `evaluate_recusals` 对轮次内作品按三类关系执行回避，幂等可重跑：
  - **作品关系**：评委本人是该作品作者/演员/权利人；
  - **人员关系**：评委声明的利害关系人是候选/参演人员；
  - **单位关系**：评委所属院团与报送单位或参演单位相同。
- 每条回避记录原因（`RecusalReason`）与细节，供最终溯源；应回避评委对该作品的评分直接拒绝。

### 匿名与身份隔离
- 组委会按轮次发放匿名代号，代号↔评委映射只有组委会可正式解析（`resolve_alias`）；**秘书处解析被拒绝**。
- 评分通道只接受代号；秘书处台账（`ledger_for_secretariat`）只含代号、节目版本、分值与状态，不含任何身份字段。
- 评分必须针对现行节目版本：轮次封存后通道关闭；被现场新事实取代的旧版本拒绝再评分；被申诉锁定的评分拒绝修改。
- 换角/重新表演后旧版本评分置 `superseded`（归档、保留数值可查，不计入现行评分）；申诉成立可置 `excluded`。

## 四、现场终评事件（LiveEventService）

- 事件只能由组委会/授权人员登记，且作品必须已经过某一**已封存轮次**的晋级结论进入终评。
- **中止**：不产生新版本，节目进入暂停状态（`is_suspended`），等待重新表演。
- **换角**：产生新节目版本；旧版本演员退出、接替演员建立新版本演职关系；旧版本评分归档；原演员的个人类候选资格**丧失（REVOKED）**，并为接替演员建立同类别候选；作品类/其他个人候选仅切换现行版本。
- **重新表演**：产生新节目版本，旧版本评分全部归档，对新版本重新打分；节目解除中止。
- 所有事件与影响（版本切换、资格丧失、新建候选、评分归档）记入候选 `effects`，溯源可见；旧版本永久可查。

## 五、申诉（AppealService）

- 申诉对象三类：**资格**（须指明候选）、**文本**（须指明作品版本）、**评分**（须指明具体评分证据）。
- 受理即**精确上锁**：候选锁原因、文本版本锁、评分证据锁；锁定评分不得修改，锁定候选不得确认获奖。
- 锁定不外溢：未被质疑的其他候选/奖项不被锁定，照常确认。
- 裁定：
  - 成立——评分类排除评分证据；资格/文本类撤销相关候选资格；登记受影响候选集合（`changed_candidacies`）；
  - 驳回/撤回——解除锁定。
- 公示期内对已确认结果成立的申诉，可经 `AwardService.invalidate_result` 撤销结果并释放名额。

## 六、奖项名额、兼得与确认（AwardService）

- 奖项分两组分别校验：
  - 作品类：节目奖、文学奖；
  - 个人类：表演奖、新人奖。
- 确认前 `can_confirm` 汇总阻断项：
  - 资格：作品类要求原创声明与权利人（文学奖另要求作者）；个人类要求现行版本仍参演、有单位证明；新人奖要求年龄证明且不超过年龄上限、且未曾获规则排除的奖项（如曾获新人奖）；后补证明采信内容在此叠加生效；
  - 锁定：候选/文本被受理中申诉锁定；
  - 名额：该奖项确认获奖数不超过 `max_winners`；
  - 兼得：同一主体不得兼得互斥奖项——同一作品不得兼得节目奖与文学奖，同一人员不得兼得表演奖与新人奖。
- 只有组委会可配置名额规则、确认或撤销获奖；撤销释放名额。

## 七、公示与停机（PublicityService）

- 公示有原定起止；系统停机按段登记开始与恢复。
- 实际截止 = 原定截止 + Σ（每段停机与公示窗口的交集时长）。窗口外停机不计；区间重叠拒绝（防重复计时）。
- **剩余公示期限不得被缩短**：早于实际截止（或尚有未恢复停机）时结束公示一律拒绝。

## 八、全链溯源（AwardService.trace_result）

从一项获奖结果必须能同时回答：
- 作品沿革：曲种、全部版本（改名、首演、原创声明）、重复关联组及确认人与实质证据；
- 人员资格：年龄证明、单位变迁、各版本演职关系、赛区经历、历史获奖、后补证明复核；
- 各轮封存：涉及该作品/人员的初评与分赛区封存指纹；
- 现场事件：换角/中止/重新表演导致的版本与资格变化；
- 评分：每条评分现行/归档/锁定/排除状态；
- 回避：哪位评委因作品、人员还是单位关系、因何细节回避；
- 申诉：哪条申诉改变了本项裁定（`changed_this_ruling`）。

## 通用原则

- 资料版本只能递增；事实只追加、不改写历史。
- 参与方、事实、约束均不能为空；示例与测试不得包含真实个人信息、账号或凭据（现有种子数据全部虚构）。
- 每个写操作都写审计日志（操作人、动作、对象、细节、时间）。
