# 曲艺评奖档案与裁定服务

在曲艺评奖收到数百个参评节目后，先解决"作品与人员的真实关系"，再组织现场比赛。本服务保存作品与人员档案，执行轮次封存、资格复核、评委回避、匿名评分、现场终评事实、名额兼得、公示申诉与获奖追溯。

## 参与方与事实

主要参与方包括参评作者与演员、报送院团、赛区工作人员、评委、秘书处、监审资格组、评奖组委会。领域资料记录以下已经确认的事实：

- 本届曲艺牡丹奖收到四百三十四个参评节目
- 评选经过初评、四个分赛区比赛和八场现场终评
- 奖项分为节目奖、表演奖、文学奖和新人奖并覆盖四十八个曲种

## 核心规则

- **作品档案**：曲种、文本沿革、首演事实、原创声明、作者与权利人；改名再报送是同一作品线下的新版本。
- **人员档案**：演职关系按版本记录（一人可随不同院团参演）、所属单位按生效区间记录、年龄证明、赛区经历、历史获奖限制。
- **疑似重复**：文本指纹相同或名称相似只生成线索；关联只能由监审资格组确认，名称相似度永远不会自动合并档案。
- **轮次封存**：初评与分赛区结束时封存材料指纹与晋级结论（不可变快照）；后补证明进入资格复核案件，只影响后续轮次，不改写原轮次。
- **回避与盲评**：按作品沿革、声明人员关系、单位关系三类计算回避并留痕；秘书处做完整性核对但不能由匿名编号反查身份，揭示只能由监审在封闭后执行。
- **现场终评**：换角取消被替演员资格、替演须资格核验；中止当次不计分；重新表演按新尝试计分；历史版本与事件始终可查看。
- **名额兼得**：公示前作品类（节目奖、文学奖）与个人类（表演奖、新人奖）分别校验配额与兼得规则。
- **公示申诉**：公示截止时间按与停机窗口的重叠时长顺延；申诉只锁定被质疑证据与所列奖项，无关奖项照常确认。
- **获奖追溯**：`trace.build_trace` 从任一获奖结果汇聚沿革、资格、封存、回避、评分、现场事件、复核与申诉，缺失环节显式标为缺口。

完整规则见 `docs/domain-rules.md`。

## 代码结构

| 文件 | 职责 |
| --- | --- |
| `src/governance/records.py` | 全部档案与裁定记录（dataclass、枚举） |
| `src/governance/repository.py` | 记录仓储与封存/锁定事实查询 |
| `src/governance/archive.py` | 作品、版本、疑似重复、人员与演职关系 |
| `src/governance/rounds.py` | 初评/分赛区封存 |
| `src/governance/eligibility.py` | 资格事实判定与复核案件 |
| `src/governance/judging.py` | 评委回避、匿名编目与评分 |
| `src/governance/finals.py` | 换角、中止、重新表演 |
| `src/governance/awards.py` | 名额、兼得校验与获奖确认 |
| `src/governance/appeals.py` | 公示停机顺延与申诉 |
| `src/governance/trace.py` | 获奖结果全链追溯 |
| `src/governance/archive_loader.py` | 从 JSON 操作流水重放完整流程 |
| `src/award_context.py` | 领域上下文读取与摘要（原有资料层） |

`contracts/context.schema.json` 描述领域上下文，`contracts/archive.schema.json` 描述操作流水支持的操作与角色；`fixtures/context.json` 是领域事实摘要（v2），`fixtures/award-archive.json` 是不含真实身份信息的合成全链路示例（含预期拒绝与断言）。

## 开发命令

运行测试：

```bash
python3 -m unittest discover -s tests -v
```

编译检查：

```bash
python3 -m compileall -q src
```

两条命令只读取仓库内文件，不需要连接外部业务系统。
