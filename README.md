# 曲艺评奖档案与裁定服务

管理曲艺评奖中**作品谱系、人员资格、分阶段封存、评委回避与匿名评分、现场终评事件、申诉锁定、公示顺延与获奖全链溯源**。

核心要解决的不是现场排程，而是"作品与人员的真实关系"：同一文本可能改名后再次报送，一名演员可能随不同院团参演，文学奖、表演奖、新人奖引用不同的资格事实。本服务把这些关系建成可追溯的事实档案，并把授权边界固化在操作上。

## 参与角色

| 角色 | 职责边界 |
| --- | --- |
| 秘书处 | 材料登记与完整性检查、代录申诉；**不能解析匿名评分身份、不能确认重复关联、不能确认获奖** |
| 授权人员 | 唯一可确认/否绝疑似重复作品关联的角色，须依据实质证据 |
| 复核人员 | 对后补证明作资格复核结论 |
| 组委会 | 轮次封存、评委与代号、回避识别、现场事件、申诉裁定、奖项配置与确认、公示 |
| 评委 | 仅持匿名代号通过评分通道打分 |

## 模块

| 模块 | 关键约束 |
| --- | --- |
| `archive_service` | 作品曲种/文本版本沿革（改名追加版本，旧版保留）、首演与原创声明、作者与权利人；人员演职关系、多院团隶属、年龄证明、赛区经历、历史获奖；名称相似度只生成线索，**关联必须授权人员凭实质证据确认** |
| `round_service` | 初评、分赛区分别封存材料与晋级结论（SHA-256 指纹快照，可校验未被改写）；后补证明进入资格复核，**不回写原轮次** |
| `jury_service` | 按作品/人员/单位三重关系自动回避并记录原因；匿名代号映射仅组委会可解析，秘书处台账只有代号与分值；旧版本评分归档保留 |
| `live_event_service` | 换角、中止、重新表演生成新节目版本：旧版评分归档、原演员个人候选资格丧失并为接替演员建档；**原版本始终可查** |
| `appeal_service` | 申诉精确锁定被质疑的资格/文本版本/评分证据；成立才改变裁定（撤销资格、排除评分），**无关奖项照常确认** |
| `award_service` | 公示前作品类（节目/文学）与个人类（表演/新人）分别校验名额与兼得规则；`trace_result` 从一项获奖追到沿革、资格、封存、回避原因与改变裁定的申诉 |
| `publicity_service` | 公示跨越系统停机时按停机与公示窗口的交集**等额顺延**，剩余期限不得缩短，未到顺延后截止不得结束公示 |

## 数据与演示

`src/quyi/store.py` 为内存存储（无外部依赖，可替换为持久化实现），`seed_store()` 提供**全部虚构**的演示关系：同一文本改名两团报送、演员跨院团、适龄新人演员等。

端到端流程演示（重复关联 → 两轮封存 → 后补证明复核 → 回避与匿名评分 → 换角/中止/重演 → 申诉锁定 → 名额兼得 → 停机顺延 → 溯源）：

```bash
python3 examples/end_to_end_demo.py
```

## 开发命令

```bash
# 单元测试（58 个，覆盖全部业务约束）
python3 -m unittest discover -t . -s tests -v

# 编译检查
python3 -m compileall -q src tests examples
```

两条命令只读取仓库内文件，不需要连接外部业务系统。领域边界与规则细节见 `docs/domain-rules.md`。

## 溯源示例

`AwardService.trace_result(candidacy_id)` 返回的链路包含：

- `work_lineage`：曲种、全部文本版本（改名/现场版本）、原创与首演、重复关联确认人与证据；
- `person_qualification` / `qualification_snapshot`：年龄证明、单位与演职关系、赛区与历史获奖、后补证明复核；
- `sealed_rounds`：涉及该作品/人员的各轮封存指纹；
- `recusals`：哪位评委因作品/人员/单位何种关系回避；
- `scores`：每条评分的状态（现行有效/旧版本归档/锁定中/被申诉排除）；
- `appeals`：每条申诉是否改变了本项裁定；
- `live_events`：换角、中止、重新表演造成的版本与资格变化。
